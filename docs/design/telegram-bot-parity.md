## Command compatibility matrix (audit before implementation)

Roles below always mean active accounts, except public self/onboarding commands. A = Admin, S = Supervisor, SF = Sales Force. All monorepo commands are private-chat only; reference permits groups. IDs below are Telegram IDs only where explicitly named.

| /test                                   | Public diagnostic response, logs text                                                                     | Intentionally omitted; no business capability                                                                                             |

HARI is case-insensitive senin/selasa/rabu/kamis/jumat/sabtu/minggu. Monorepo `/jadwal [HARI|semua] [after=KURSOR]` requires day/semua before cursor. Named `/jadwalsales` options can occur in any order. Planning IDs/cursors use exact simple ASCII tokens or canonical `~` + unpadded base64url UTF-8. They are not usernames, Telegram IDs or credentials. Names consume remaining text, spaces allowed; underscores are not required.

## Deferred domain fields and prerequisites

| Reference fields                           | Intended future mapping / prerequisite                                                                                                                                                          |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Outlet outlet_id and no_rs                 | Distinct business code and No. RS, never internal ID or assumed phone. Confirm format, uniqueness, leading zeros; additive schema/contracts/API and import crosswalk before Bot grammar changes |
| users.salesforce_code                      | Explicit verified User→business SF association already exists; confirm legacy-code crosswalk before import/filter compatibility                                                                 |
| date, period_week 1–5                      | Visit visitedAt already captures actual WIB instant; decide period/month anchor, late entry and date-only import policy; do not invent historical clock times                                   |
| Perdana SA / VF Data / VF Voice Stock      | Candidate linked Stock Report observations; resolve family vs SKU and meaning of Stock before mapping to productId/quantity                                                                     |
| Selling / Sellout triples                  | Independent observation fields only after definitions, units and interval agreed; no inferred stock-delta formula                                                                               |
| DigiPOS balance / Total Belanja            | Separate report-time monetary observations; confirm currency, precision, scope and source; no financial formulas or DigiPOS integration implied                                                 |
| active_cvm / active_voice / active_digital | Three report-time observations, not a master Outlet active flag; partner must define each criterion and interval                                                                                |

Preserve ADR-0003: Visit and Stock Report remain separate, optionally linked. History/export/product-management chat commands are absent in reference too; do not add placeholders.

## Reproduction

Use Node 24 / pnpm 10.30.1. Run `pnpm install`, `pnpm -r --if-present test`, `pnpm typecheck`, `pnpm check`, `pnpm --filter @sales-visit/db db:check`, `pnpm build:web`, `pnpm test:deployment`. Integration tests bundle real Workers and named RPC with disposable migrated D1; only Telegram transport is simulated. No remote resources needed.

Local sandbox: `pnpm db:migrate:local`, `pnpm db:seed:local`, optional local schedule fixture as documented in [Bot README](../../apps/bot/README.md#reproducible-local-sandbox). Provision synthetic Admin with [controlled bootstrap](../../packages/db/IDENTITY.md), targeting API-local D1, not package sandbox. Run `pnpm dev:api` and `pnpm dev:bot` in separate terminals. Follow the README for private test-only secrets and optional consenting Telegram/tunnel test; never print credentials or use the original bot token. Automated tests require no credentials. No remote migration, deployment, webhook or CI/CD settings change is part of this work.
